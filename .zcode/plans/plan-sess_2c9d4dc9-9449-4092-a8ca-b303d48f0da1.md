# Landing Page Implementation Plan

## Overview
Add a public landing page at `/`, move the editor to `/editor`. Reuse existing `zenuxs-oauth` for authentication. No new auth system.

## Architecture

```
/               → LandingPage (new)
/editor         → WorkspaceView (existing, moved from /)
/demo           → WorkspaceView (existing, unchanged)
/share/:roomId  → WorkspaceView (existing, unchanged)
```

## Phase 1: Router Update (`src/router.ts`)

- Add `/editor` route pointing to `WorkspaceView`
- Change `/` to point to new `LandingPage`
- Keep `/demo`, `/share/:roomId` unchanged
- Keep `/storage` redirect

## Phase 2: Landing Page Component (`src/components/LandingPage.vue`)

Create a single-file landing page with all sections inline (no new dependencies). Sections:

1. **Header** - Logo + brand + Beta badge, nav links (Features/AI/Components/Code), Sign in + Get Started buttons
2. **Hero** - "Design at the speed of thought." headline, subtitle, two CTAs (Get Started →, Explore the editor)
3. **Product Preview** - Styled mockup of the editor (dark chrome, sidebar, canvas, toolbar, AI panel)
4. **AI Section** - "Your AI design copilot." with 4 feature cards
5. **Features Grid** - 6-9 feature cards
6. **Workflow** - 3-step: Describe → Design → Ship
7. **Final CTA** - "Ready to design differently?" + Get Started
8. **Footer** - Minimal

## Phase 3: Auth Integration

- Import `loginWithZenuxs`, `isAuthenticated` from `@/app/auth/zenuxs`
- "Get Started" button handler:
  - If `isAuthenticated.value` → `router.push('/editor')`
  - Else → `await loginWithZenuxs('ui')` → then `router.push('/editor')`
- "Sign in" in header: same flow
- "Explore the editor" → `router.push('/editor')` (no auth required)

## Phase 4: Redirect Authenticated Users

In `App.vue` or `LandingPage.vue`:
- If user is already authenticated and visits `/`, optionally auto-redirect to `/editor`
- OR let them see the landing page and click through (matches spec)

## Constraints
- No new npm dependencies
- Single component file for landing page (inline styles via Tailwind)
- Use existing theme tokens from `app.css`
- Use existing Lucide icons
- Reuse `loginWithZenuxs()` exactly as-is
- Preserve all existing routes (/demo, /share/:roomId)
- Editor at /editor must work identically to current /
